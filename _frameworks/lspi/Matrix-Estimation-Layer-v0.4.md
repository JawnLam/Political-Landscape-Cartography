# The Matrix-Estimation Layer — Corrected Canonical (v0.4)

*Supersedes v0.3. This revision is **content, not notation** — the reconciled lexicon of v0.3 (§13) carries over unchanged. v0.4 fixes the defects found in `Content-Audit-v0.3.md`: the gate (M1), the probe criterion (M2), the depth-bias asymmetry (M3), four definitional imprecisions (m4–m7), and adds the one missing proof — termination of the estimation loop (n10). One hidden object: the target's **decision matrix** `[A/i/t/D]`. Three faces — **estimate it** (detection, §4–§5), **move it** (resources, §6), **account for its being defended** (depth, §5). ## 3. The shared state — and three quantities v0.3 conflated *(fixes m4)*

The estimand is the target's utility over **keeping vs. relinquishing** the resource: `P` = relinquish (actor's preferred position), `X` = keep. Select `P ⟺ u(P) > u(X) ⟺ margin(h) < 0`, where `margin(h) = u(X) − u(P)`.

v0.3 collapsed three distinct quantities into "price." They are now separated:

- **Required shift** `price* = margin(h)` — the favorable shift (in utility-difference units) the move must produce to drive selection to `P`. This is the deficit to close, *not* a payment.
- **Actor's cost** `Σ_{r∈Π} cost(r)` — the resources the actor spends producing that shift.
- **Target's obtained utility** `[…/O/U]` — what the target *gains*, which equals the shift **only for the inducement portion** (raising `u(P)`). Coercive shift (raising `[X/c]`, lowering `[X/b]`) *reduces* the target's utility on its alternative while the actor still pays a cost. So obtained-utility ≤ required-shift in general, with equality only for pure inducement.

The actor drives `margin` below zero at minimum `Σ cost(r)`, subject to the required shift being achievable.

## 4. The shared loop — selection and stopping now in one currency *(fixes M2)*

```
δ  → ℬ = ⟨ℋ, cr⟩              detection returns the differential + credences
η  → z                        probe: a low-stakes ε whose payoff is decision-relevant information
ν_η(z | h)                     observation model (h carries depth ℓ_h)
cr′(h) ∝ ν_η(z | h) · cr(h)    update = Bayesian conditioning
```

Let `V(ℬ)` = the expected payoff of acting optimally under belief `ℬ` (the best affordable sufficient plan's net value, §8). A probe's worth is its **value of information**, not its entropy reduction:

```
VoI(η) = E_z[ V(ℬ_z) ] − V(ℬ) − cost(η)
```

**Select** `η* = argmax VoI(η)`. **Stop and act** when `max_η VoI(η) ≤ 0` — no probe's expected decision-improvement covers its cost. Selection and stopping are now the *same* currency (decision payoff), fixing v0.3's mismatch.

The consequence is the right one: VoI is concentrated on uncertainty **near the selection boundary** (`margin ≈ 0`), because only there does resolving it change which plan is optimal. Resolving a matrix cell that doesn't alter the pivotal-resource ranking has `VoI ≈ 0` even if its entropy is large. (Expected information gain is recovered only as the special-case proxy when all uncertainty is equally decision-relevant — which the worth function says it isn't.) This VoI is **one-step** (myopic); full sequential VoI is a POMDP-planning problem, deferred, and the myopia is what the termination budget in §12 guards.

**The adversary lives in `ν`.** At `ℓ_h = 0` the signal is genuine; at `ℓ_h ≥ 1` it is strategic, its branches generated by the catalogue's perception-management tactics. Prefer **costly signals** (cheap talk babbles under misaligned interests). Beware **probe leakage** (frontier §11).

## 5. Join 1 — the depth-decoder, now loss-calibrated *(fixes M3, n8)*

Depth is the decoder ring: estimating `ℓ_T` is estimating how much to decode versus trust. Two rules stand; the third is corrected.

1. **Estimate depth first.** Front-load a depth-discriminating probe (transparent bait, consistency check, costly-commitment ask); read content through the resulting decoder.
2. **A depth-update forces re-decoding of prior signals** — *in a factored/plug-in implementation.* (Exact joint Bayesian updating is order-invariant; the "re-read the past" dynamic is an artifact of approximating depth separately, which real implementations do. Stated precisely so it isn't mistaken for a property of the exact posterior.)
3. **Choose `ℓ_A` by minimizing two-sided expected loss — not by unconditional "err high."** Both errors cost:
   - *Under-estimating* `ℓ_T`: you decode managed signals as genuine and get played (loss `L_under`, scales with adversarial stakes).
   - *Over-estimating* `ℓ_T`: you decode genuine signals as managed and discard true information — paranoia (loss `L_over`, scales with the value of information you'd throw away).

   `ℓ_A = argmin_ℓ E_{ℓ_T∼cr}[ loss(ℓ, ℓ_T) ]`. Operationally, `ℓ_A = ℓ̂_T + b`, where the upward bias `b ∈ [0,1]` grows with the engagement's **adversarial intensity** (which OPC's political-intensity diagnostic already measures): `b → 1` in adversarial spheres (recover "one level above"), `b → 0` in cooperative ones (read a truthful counterpart at face value). The v0.3 unconditional "err high" is the `b = 1` special case, correct only when `L_under ≫ L_over`.

## 6. The actuator — resources, worth, convertibility *(fixes m5, m6, m7)*

**Definition (primary):** a political resource is a costly, target-conditional capacity to apply a signed delta to a cell of a target's decision matrix. The nine types are a non-exhaustive basis of carriers.

**Effect signature** `sig_t(r)`: signed target-conditional deltas over `{P/b, P/c, X/b, X/c}` at `cost(r)`.

**Combined shift is a set function** *(m6).* For a plan `Π`, `shift(Π, h)` is the combined favorable shift toward `P`. The **additive** case `shift(Π,h) = Σ_{r∈Π} shift_r(h)` is the default first-order approximation; in general resources interact (synergy/redundancy), so `shift` is a set function and additivity is flagged wherever assumed.

**Worth is contextual pivotality** *(m7).* worth is a resource's marginal contribution *within a plan*, not a scalar property of the resource:

```
worth_t(r | Π) = E_{h∼cr} [ marginal contribution of r to closing margin(h), given the rest of Π ]
```

(The Shapley value of `r` in the threshold game defined by `shift(·,h) ≥ margin(h)`, in expectation over `ℬ`.) A resource with large nominal `shift_r` can still have small worth-in-context (redundant given the plan) or partial worth (shrinks the margin without closing it, lowering the cost of the pivotal member). This is the formal content of *"I applied real leverage and nothing happened."*

**Convertibility, and compounding = *gain*-cycles** *(m5).* Resources convert through cycles, `r₁ ⇝ r₂`, with sphere-indexed exchange rates. Edge types: transfer, transform, earn/sanction, non-transferable. A resource **compounds iff it lies on a directed cycle whose product of exchange rates exceeds 1** — a net-gain (arbitrage) loop; a bare cycle with product `≤ 1` is depreciating, not compounding. Detect compounding as positive-gain cycles (negative cycles under `−log`-rate weights). Nodes carry durability; **protection** = spending durable low-yield resources to defend fragile high-yield ones.

## 7. Join 2 — the seam (the estimator prices the actuator) *(fixes n9)*

`worth_t(r | Π)` is an expectation over `ℬ`, so **detection is price discovery for the inventory**: every probe *sharpens* the worth estimate — reduces its variance, revealing the true worth, which may be high *or* low (a probe can reveal a held resource is worthless here). Two ends of one computation; you cannot price the pivot without an estimate of the margin.

## 8. Join 3 — the augmented gate: sufficiency + inclusion *(fixes M1, the load-bearing repair)*

v0.3's gate compared a single resource's marginal worth to the *total* required shift — a scale error that its own Rusty example falsified. Replace it with two tests over a **plan** `Π` (the set of deployments the actor intends):

- **Sufficiency (plan-level):** `Π` is expected to close the margin —
  `E_{h∼cr}[ margin(h) − shift(Π,h) ] ≤ 0` (plus a risk term for belief variance).
- **Inclusion (member-level):** every `r ∈ Π` earns its place —
  `worth_t(r | Π∖r) ≥ cost(r)` (its marginal contribution given the rest exceeds its own cost).
- **Affordability:** `Σ_{r∈Π} cost(r) ≤` the interest's value to the actor (never pay more than the prize).

```
GATE PASS  ⟺  ∃ affordable, sufficient plan Π ⊆ (held resources)
                with every member clearing inclusion.
```

**Routes on failure** (the control flow of the whole system):

| Situation | Route |
|---|---|
| A sufficient plan needs a resource not held | nested acquisition — classic LSPI `¬HAVE` (traverse `⇝`) |
| Held resources are *collectively* sufficient though no single one suffices | **PASS** — this is the M1 fix (Rusty's three-resource plan passes) |
| No affordable sufficient plan even with acquisition | abandon, or **rescope** the objective (shrink the interest) |
| Sufficiency is uncertain because `margin` is uncertain under `ℬ` | route back to detection — re-probe (the belief-variance route, preserved) |

This passes Rusty correctly (no single intention suffices; the plan `{new-procedures, reorg, job-offer}` closes Todd's margin, and inclusion asks — usefully — whether Intentions 1 and 2 were each worth their cost or were partly wasteful). It reduces to a sensible single-resource gate when `Π = {r}` (sufficiency `shift_r ≥ margin`, inclusion `worth_t(r|∅) ≥ cost(r)`).

## 9. The integrated loop

```
   detection (+depth) ──sharpens──► ℬ ──prices──► worth_t(r|Π) ──► GATE (sufficiency+inclusion) ──► execute Π
        ▲  ▲                                                              │   │
        │  └──── sufficiency uncertain under ℬ: re-probe (η, by VoI) ─────┘   │
        │                                                                     │
        └──────── plan needs an unheld resource: acquire via  r₁ ⇝ r₂ ────────┘
```

Every pass logs to an audit trail — differential, probe and its VoI, predicted vs. observed signal, update, the plan and the gate decision — the reconstructable-judgment property that made LSPI defensible, extended to the estimation LSPI left to the oracle.

## 12. Termination of the estimation loop *(supplies n10 — the one missing proof)*

The new re-probe route (`sufficiency-uncertain → probe`) is a loop LSPI's strong-normalization proof (§13.5) does not cover. It terminates, by an argument in LSPI's own style (a well-founded lexicographic measure and a bounded budget).

**Per-cycle probe bound.** Let `V*` be the decision value under perfect information (finite — bounded by the interest's value to the actor) and `cost_min > 0` a floor on probe cost. Every probe the loop *takes* has `VoI(η) > 0`, i.e. its gross expected decision-gain `E_z[V(ℬ_z)] − V(ℬ) > cost(η) ≥ cost_min`. Gross gains are non-negative (information cannot lower a Bayesian's expected optimal value) and cumulatively bounded by `V* − V(ℬ_0)`. Hence the number of probes with gross gain `> cost_min` is at most

```
N_probe ≤ ⌈ (V* − V(ℬ_0)) / cost_min ⌉   <  ∞.
```

Impose this as a per-cycle **probe budget** (analogous to LSPI's `PerIntentionBound`); the VoI stop-rule means it is rarely binding, but it makes termination hold *by construction*, not merely in expectation.

**Composition with LSPI.** Extend LSPI's lexicographic termination measure `μ` with the probe budget as an added component that strictly decreases on each probe and resets per cycle (exactly as `rem_budget` behaves for intention-firings). Then:

```
total probes  ≤  (LSPI cycle/sub-cycle count, bounded by μ)  ×  N_probe   <  ∞.
```

The estimation loop nests a bounded probe-loop inside each strongly-normalizing LSPI cycle, so the combined system is strongly normalizing on the extended measure. The buildable core therefore inherits LSPI's termination guarantee rather than merely its style — closing the "defensible like LSPI" promise. *(This is the one piece of genuinely new math in v0.4; it is a sketch at the rigor of LSPI's own §13.5 measure arguments, not a machine-checked proof.)*
